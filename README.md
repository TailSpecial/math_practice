# Практика · КубГУ / ФМиКН

Самостоятельное приложение по ТЗ из `Учебная практика_тех_задание_1.docx`. Moodle не используется. Сервер: Django 5.2, база по умолчанию SQLite, интерфейс на русском языке. Документы формируются в редактируемом DOCX.

## Запуск в Windows / PowerShell

```powershell
uv venv .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
Copy-Item .env.example .env
.venv/Scripts/python.exe manage.py migrate
.venv/Scripts/python.exe manage.py seed_demo
.venv/Scripts/python.exe manage.py runserver 127.0.0.1:8000
```

Открыть http://127.0.0.1:8000. Если `uv` не установлен, используйте `python -m venv .venv` и `.venv/Scripts/python.exe -m pip install -r requirements.txt`.

Демонстрационные аккаунты: `student`, `teacher`, `teacher2`, `head`. Пароль: `Practice2026!`. Демо содержит 8 студентов, 240 задач (6 тем по 40 задач), варианты, отчёты с разными статусами и методический материал. Повторный `seed_demo` не сбрасывает пароли и не меняет выданные варианты. Демо доступно только при DEBUG=1.

**Это демонстрационные данные:** тексты компетенций и бланки необходимо сверить с утверждёнными документами факультета. Задачи параметризованы и предназначены для начального наполнения; кафедра должна проверить соответствие своей программе. В ТЗ не было приложенных официальных бланков, перечня компетенций и полного банка задач.

## Три роли

| Роль | Возможности |
| --- | --- |
| Студент | Только собственное задание и документы, загрузка собственного отчёта, замечания преподавателя, материалы. |
| Преподаватель | Только назначенные ему студенты своей кафедры, формирование и просмотр их вариантов, скачивание и проверка отчётов, оценка и возврат на доработку. |
| Заведующий кафедрой | Студенты и группы своей кафедры, импорт CSV, назначение и смена преподавателя, редактирование бланка и задач своей кафедры, библиотека материалов. |

Заведующий не формирует варианты за преподавателя. Перераспределение студента сразу передаёт доступ к заданию и истории отчётов новому руководителю, предыдущий руководитель теряет доступ. Учётная запись технического суперпользователя в `/admin/` предназначена для первоначального наполнения справочников, а не является четвёртой прикладной ролью.

## Рабочий процесс

1. Заведующий создаёт группу: направление, курс, учебный год (год начала), даты и темы практики.
2. Загружает UTF-8 CSV с разделителем `;` или запятой. Образец скачивается со страницы группы. Столбцы: `student_login`, `student_name`, `supervisor_login`, `supervisor_name`, `department`. Логины должны точно совпадать с идентификаторами, передаваемыми системой входа университета. Кафедра должна совпадать с кафедрой заведующего и группы. Импорт атомарный: ошибочная строка отменяет весь импорт. Повторные записи пропускаются. Импортированные аккаунты получают непригодный локальный пароль и используют университетский вход после его подключения.
3. Заведующий при необходимости меняет назначение преподавателя в карточке студента. Для назначения доступны только активные преподаватели его кафедры.
4. Преподаватель открывает группу и формирует варианты своим студентам. Банк должен содержать минимум 25 подходящих активных задач по каждой теме. Учитываются курс, направление, кафедральные и общие задачи. Каждому выдаётся одна задача из каждой темы; в пределах учебного года одна задача используется лишь один раз во всём приложении. При нехватке свободных задач операция отменяется целиком с объяснением.
5. Варианты и бланк сохраняются как снимки. Повторная генерация обрабатывает только новых студентов. Правки банка, бланка и настроек не меняют уже выданные задачи. Для следующего года создаётся новая группа; прежние варианты остаются доступны в архиве.
6. Студент скачивает задание и комплект DOCX: титульный лист, лист инструктажа, оценочный лист и индивидуальное задание. Загружает PDF или DOCX до 20 МБ. Преподаватель принимает отчёт с оценкой 2–5 либо возвращает с обязательным комментарием. Повторная загрузка доступна после возврата на доработку; сохраняется история версий.

Заведующий также может вручную добавить преподавателя через раздел «Преподаватели», а студента — кнопкой в группе. Для новых аккаунтов локальные пароли не создаются: используются университетские логины. На странице группы можно отметить несколько студентов и назначить им одного руководителя; выбор чужого студента или преподавателя отменяет всю операцию. Параметры группы доступны для редактирования, но учебный год после добавления студентов закрепляется. Преподаватель перед генерацией видит число подходящих и свободных задач по каждой теме и число студентов без варианта.

Бланк задания редактируется как заголовок, инструкция и заключительный текст. Шаблоны остальных листов определены в `practice/documents.py`. Данные студента, руководитель на момент выдачи, сроки, направление и компетенции подставляются автоматически. Если руководитель меняется после выдачи, карточка показывает актуального руководителя, а ранее выданный DOCX сохраняет исходные сведения.

## Вход через аккаунты КубГУ

На образовательном портале https://openedu.kubsu.ru/login/index.php есть вход «КубГУ». Его публичная страница не предоставляет параметры подключения стороннего приложения. **Реальный университетский вход требует согласования с ИТ-службой**: нельзя подключить существующие университетские аккаунты только по адресу Moodle или копировать пароли пользователей.

Реализован адаптер OpenID Connect на Authlib: authorization code + PKCE, проверка state, nonce, подписи ID token, issuer и audience. Поддержка OIDC конкретным провайдером КубГУ пока не подтверждена. Если университет предлагает только SAML или LDAP, понадобится соответствующий адаптер вместо текущего OIDC-модуля; остальная система от протокола не зависит.

Получите у ИТ-службы:

- адрес OIDC Discovery (`.well-known/openid-configuration`);
- client ID и client secret зарегистрированного приложения;
- название claim со стабильным университетским логином;
- регистрацию redirect URI: `http://127.0.0.1:8000/auth/kubsu/callback/` для разработки или `https://ваш-домен/auth/kubsu/callback/` для сервера.

Заполните `.env`:

```dotenv
KUBSU_OIDC_METADATA_URL=https://адрес-провайдера/.well-known/openid-configuration
KUBSU_CLIENT_ID=выданный-идентификатор
KUBSU_CLIENT_SECRET=выданный-секрет
KUBSU_LOGIN_CLAIM=preferred_username
```

Адрес выше — пример, а не реальный адрес КубГУ. Перезапустите сервер: появится кнопка университетского входа. Впервые аккаунт связывается только с предварительно импортированным университетским логином, затем используется проверенная пара issuer/subject. Роли из внешнего профиля игнорируются. Приложение не запрашивает и не хранит пароль КубГУ. Подключение протестировано имитацией ответа провайдера, но не реальным университетским аккаунтом.

## Начальная настройка без демо

```powershell
.venv/Scripts/python.exe manage.py createsuperuser
```

В `/admin/` создайте пользователя заведующего и профиль с ролью «Заведующий кафедрой» и непустой кафедрой. Создайте направления и актуальные компетенции, темы и задачи. Общие задачи имеют пустую кафедру; заведующие могут редактировать только задачи своей кафедры. Студентов и преподавателей можно создать импортом. Списки и документы изолированы на сервере: знание URL чужого файла не открывает доступ. Папка `media/` не публикуется как статический каталог.

## Проверка

### Формулы LaTeX

В условиях задач и тексте бланка поддерживаются строчные формулы `\(x^2\)` или `$x^2$` и отдельные блоки `\[\frac{a}{b}\]` или `$$\int_0^1 x^2\,dx$$`. Многострочные матрицы можно записывать через `\begin{pmatrix}…\end{pmatrix}` (круглые скобки) или `\begin{bmatrix}…\end{bmatrix}` (квадратные скобки) внутри математических разделителей. Старые числовые матрицы вида `A = [[20, 1], [1, 20]]` автоматически отображаются отдельным математическим блоком с выровненными строками и столбцами. Это преобразование касается только отображения и не изменяет выданные задания. Непрямоугольные массивы и массивы с текстом остаются обычным текстом. В редакторе задач и бланка есть живой предпросмотр. Банк задач и личное задание студента отображают формулы автоматически. Ошибочное выражение подсвечивается, сохраняя исходный код.

Используется локальная копия KaTeX (версия — `static/vendor/katex/VERSION`, лицензия MIT рядом), включая шрифты; внешнее подключение для формул не требуется. HTML из условий экранируется, доверенные HTML-команды LaTeX отключены. Документация синтаксиса: https://katex.org/docs/supported. В скачиваемых DOCX пока сохраняется исходный LaTeX-код, без преобразования в формулы Word.

```powershell
.venv/Scripts/python.exe manage.py check
.venv/Scripts/python.exe manage.py test
```

Проверяются разграничение ролей и кафедр, генерация только своим студентам, уникальность и неизменность вариантов, атомарный импорт, ручное добавление участников, массовое распределение, защита учебного года от изменений, поиск русских ФИО без учёта регистра, скачивание защищённых документов, сдача/доработка/приём отчёта и привязка OIDC без повышения роли. Поиск по текстам задач воспринимает `%` и `_` как обычные символы.

Для проверки интерфейса в установленном Google Chrome запустите приложение с демонстрационными данными, затем в другом терминале:

```powershell
uv pip install --python .venv/Scripts/python.exe -r requirements-dev.txt
.venv/Scripts/python.exe scripts/browser_check.py
```

Проверка входит под тремя демоаккаунтами, проверяет навигацию, выбор студентов для массового назначения, скачивание задания и отсутствие горизонтального прокручивания всей страницы на экране 390 px. Данные приложения не изменяются. Снимки сохраняются в `artifacts/browser/`. Для Edge используйте `--channel msedge`; для Chromium установите браузер командой `python -m playwright install chromium` и передайте `--channel chromium`.

## Развёртывание

Для локальной разработки SQLite достаточно. Для параллельной работы большого числа преподавателей используйте PostgreSQL (понадобится драйвер и изменение DATABASES); уникальность задач дополнительно защищена ограничением базы данных. SQLite не поддерживает полноценные блокировки select_for_update.

Установите уникальный SECRET_KEY, DEBUG=0, ALLOWED_HOSTS и CSRF_TRUSTED_ORIGINS своего домена; включите HTTPS и SECURE_SSL_REDIRECT=1. Соберите статику командой `manage.py collectstatic`. Запускайте через WSGI-сервер (например, Waitress на Windows), а не встроенный runserver. Настройте резервные копии БД и закрытого каталога media. Секреты не включайте в репозиторий. Ограничение попыток локального входа использует Django cache; для нескольких процессов настройте общий cache и ограничение запросов на reverse proxy. Проверку загружаемых документов антивирусом и официальные университетские формы следует подключить в инфраструктуре вуза.
